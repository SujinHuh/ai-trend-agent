구현 내용

사용자 프로필

high/normal/muted tags, enabled domains, blocked keywords, 발송 시각을 SQLite에 저장합니다.

피드백 이벤트

항목별 action을 append-only로 기록하고 unique event key로 재시도를 멱등 처리합니다.

개인화 재정렬

전체 후보 pool에서 필터와 제한된 boost를 적용한 뒤 최종 limit을 계산합니다.

운영 연결

Slack build/send, Hermes cron, CLI에 명시적 user profile opt-in을 연결했습니다.

정책 경계

  • 기존 importance, confidence, confirmation, action level은 변경하지 않습니다.
  • hide는 항목만 제외하며 태그 전체를 자동 mute하지 않습니다.
  • profile domain은 runtime에서 활성화된 domain을 다시 켤 수 없습니다.
  • feedback은 profile 발송 시각 이전 이벤트만 해당 report date에 반영합니다.
  • profile 미지정 경로는 Task 008 payload와 순서를 유지합니다.

독립 검수 반영

시간과 재시도

timezone offset을 UTC ISO로 정규화하고 순차·동시 event retry 경계를 보강했습니다.

후보 pool

SQL top-N 이후 재정렬 문제를 제거해 관심 후보가 base top-N 밖에서도 승격될 수 있습니다.

스키마 안전성

CHECK, UNIQUE, FK drift assertion과 version 7에서 8로의 upgrade 테스트를 추가했습니다.

도메인 경계

full runtime metadata와 profile-filtered sources를 분리해 잘못된 AI fallback을 막았습니다.
