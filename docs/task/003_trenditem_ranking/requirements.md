# Task 003 Requirements - TrendItem Ranking and LLM Wiki Synthesis

## Purpose

Task 003 turns ingested source items into ranked daily digest candidates and LLM Wiki synthesis records.

This task does not collect new external sources. It uses Task 001 storage and Task 002 ingestion output.

## Inputs

- `TrendItem`
- `SourceEvidence`
- source credibility from Source Registry
- optional future social signal lineage from Task 007

## Required Outputs

1. `summary`
2. `whyItMatters`
3. `practicalImpact`
4. `trendCategory`
5. `actionLevel`
6. `confidence`
7. `importanceScore`
8. `sourceLineage`
9. `confirmationStatus`
10. `contradictionNotes`
11. `stalenessPolicy`
12. daily digest candidates

## Enum Requirements

`actionLevel`:

- `do_now`
- `do_next`
- `watch_later`
- `needs_confirmation`

`confirmationStatus`:

- `confirmed`
- `official_only`
- `needs_confirmation`
- `conflicting`
- `excluded`

`trendCategory`:

- `model`
- `coding_agent`
- `product`
- `open_source`
- `benchmark`
- `infra`
- `safety`
- `business`
- `research`

## Trust Gate

Social or trusted individual signals must not be promoted as confirmed facts unless connected to an official source, official GitHub release, paper, benchmark page, or source-of-record.

Rules:

1. `confirmationStatus = needs_confirmation` cannot become `do_now`.
2. `needs_confirmation` without official lineage is capped at `watch_later`.
3. Slack-ready digest candidates must be `confirmed` or `official_only`.
4. social-only items can influence velocity but not factual confidence.

## Scoring Contract

The first Task 003 ranker is deterministic and rule-based.

`importanceScore`:

- range: `0` to `100`
- higher score ranks earlier
- clamp final score to the allowed range

Base score:

- official source evidence: `+35`
- source evidence exists but is not official: `+15`
- title or excerpt includes release, launch, model, API, benchmark, open source, safety, agent, or coding signal: `+15`
- published within the report date KST window: `+20`
- published within the previous 3 days: `+10`
- missing published date: `+5`

Category weights:

- `model`: `+15`
- `coding_agent`: `+15`
- `product`: `+12`
- `open_source`: `+10`
- `benchmark`: `+10`
- `infra`: `+8`
- `safety`: `+8`
- `research`: `+7`
- `business`: `+5`

Penalty:

- `needs_confirmation`: `-20`
- `conflicting`: `-40`
- stale item beyond 14 days: `-20`

Source priority:

- source registry priority adds up to `+10`
- this keeps high-priority official sources ahead when all other signals tie

`confidence`:

- range: `0` to `1`
- official source evidence starts at `0.85`
- multiple evidence rows add up to `+0.05`
- `needs_confirmation` is capped at `0.6`
- `conflicting` is capped at `0.4`

Tie-break order:

1. higher `importanceScore`
2. higher `confidence`
3. newer `publishedAt`
4. lexicographic `trendItem.id`

`actionLevel`:

- `do_now`: score `>= 80` and `confirmationStatus` is `confirmed` or `official_only`
- `do_next`: score `>= 60` and not `needs_confirmation`
- `watch_later`: score `>= 30`
- `needs_confirmation`: any unconfirmed item regardless of score

## Karpathy LLM Wiki Mapping

- raw source: Task 002 cache and `SourceEvidence`
- wiki synthesis: Task 003 assessment fields
- schema: this task's enums, trust gate, and scoring rules
- query/index/lint: start with minimal query/index output; full lint can be a later task

## Acceptance Criteria

- deterministic ranking exists before any LLM provider is added.
- digest candidates can be generated by date.
- source lineage is visible in output.
- `needs_confirmation` gate is tested.
- generated records preserve original source evidence links.
- ranking order is stable for tied inputs.
- empty report dates return an empty candidate list, not an error.
- assessment save is idempotent for the same trend item and report date.
